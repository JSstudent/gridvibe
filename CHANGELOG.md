# Changelog

All notable changes to GridVibe will be documented in this file.

## Unreleased

- **The workspace window you land in pulses, so a swap is visible.** Two GridVibe windows look alike — same chrome, same grid, only the content differs — so `Alt+W`, **Workspace ▸ Open Workspace** and **Open** in the launcher's Workspaces card all handed focus to another window with nothing announcing it; on a second screen, or with both windows visible at once, the only way to tell the switch had happened was to read the tab names. The window receiving focus now flashes a ring around its viewport once. It is armed at the departing end in the two dispatchers every swap already goes through (`focusWorkspaceWindow` / `openWorkspaceWindow` in `workspaces.js`), so a surface added later cannot forget it, and claimed at the arriving end by the window that matches the request — once, and only within a short window, so a request nobody arrives on expires instead of pulsing at some unrelated moment. The request is stored rather than broadcast, which is what lets a workspace that had no window yet pulse when its fresh page boots. The ring never takes a click, and `prefers-reduced-motion` gets a single quiet fade instead of the two beats.
- **Restoring a workspace gives you back the workspace you saved, not the presets you edited since.** A restored tab that had come from a saved session was rebuilt from that session's *current* configuration — "latest preset wins" — so editing a preset silently rewrote every saved workspace that referenced it. A three-pane workspace you saved last week came back as whatever the preset had since been edited down to, with the preset's name instead of the tab's, and its stored split geometry thrown away because the pane count no longer matched. No workspace save was involved: the shape simply changed underneath you. The captured snapshot is now the only source of a restored tab's shape — names, pane count, modes, directories, commands, and both layouts are replayed exactly as captured. A preset still contributes the one thing a snapshot deliberately never holds, its SSH password, and only onto a pane that still names that preset's host, user, and port; a preset that has since been pointed at another machine keeps its password to itself, and the pane comes back with its own shape and its usual **Retry** rather than being reshaped to fit a credential. Editing a saved session now changes the next launch and nothing else.
- **Asking to restore twice reopens a workspace once, and both modes ask the same way.** Restore checked whether a workspace had tabs yet and then, in separate steps, created it and launched its groups — so two requests arriving together (a double click, two launcher windows, a window and a browser tab) both passed the check: the main workspace came back with every tab duplicated, and a named workspace failed outright with an internal "Workspace already exists". A restore now claims its workspace for the duration and the second request is told, plainly, that one is already running. With multiple workspaces off, the launcher's restore banner also stopped rebuilding the workspace itself: it used to loop over the individual launch calls in the browser, re-resolving presets on the way, which meant it could stop half way through a network failure, could restore on top of a workspace that already had tabs, and did not apply the saved workspace name. Both modes now go through the one server-side restore, which reports what actually started, tab by tab.
- **Two saved workspaces that use the same saved session are no longer restored half-way.** A saved session can be open in only one workspace at a time, but nothing stopped two saved *workspaces* from both remembering one — closing workspaces deliberately keeps their snapshots, so this accumulates on its own. Selecting both in the restore chooser used to reopen whichever the request happened to list first and quietly hand the other one back a tab short. The selection is now checked before anything is launched: the whole request is refused, the clash is named, and nothing changes until you deselect one side and restore them one at a time. A saved session already open in a workspace you did *not* select is unchanged — that tab is still reported as skipped while the rest of its workspace comes back.
- **A session tab now appears complete or not at all, and two saved sessions can no longer overwrite each other.** Launching a group used to happen in steps — create the tab, then add its panes one at a time — with the workspace unlocked between each one. An autosave tick that landed in the middle stored what it happened to see: an empty tab, one pane of three, or, when you relaunched a saved session, a tab whose old panes had already been torn down and whose new ones did not exist yet. Restoring that snapshot gave you back the half-built version. A launch is now a single transaction: the tab and every pane it contains are published together, so a save can only ever capture the shape you had before or the shape you have now. Relaunching a saved session is the same swap — its old panes are only replaced once the new ones are ready, so a relaunch that turns out to be unusable leaves the running one alone instead of emptying it. Separately, a saved session's id was flattened into its tab's id by replacing punctuation with `-`, so two presets whose ids differed only in punctuation (`a/b` and `a-b`) claimed the *same* tab: the second launch replaced the first in place, and across workspaces it closed the other workspace's live sessions before noticing the tab was not its own. Ids are now encoded reversibly, so distinct saved sessions always get distinct tabs — ordinary ids are unchanged, so nothing you already have moves. And the five-second window that protected a tab still being assembled is gone with the reason for it: an emptied tab is swept immediately, and a workspace you are launching into is held by the launch itself.

- **A workspace you closed is closed everywhere, and every "close" now tells you what it keeps.** The permanent internal `default` record used to be rendered as a workspace: after the last tab in the main workspace closed, the Workspaces card showed nothing while the launch menu still offered an empty *Main workspace — 0 sessions*, and the two lists disagreed about the same state. One predicate now decides what a user-visible workspace is — it holds a tab, or you created it deliberately empty — and the API, the Workspaces card, the launch destination menu, the Open/Move menus and the `Alt+W` cycle all read it, so a container or a launch still in flight can no longer masquerade as a workspace. Closing a pane became as explicit as closing a tab: closing the last pane within five seconds of launching used to remove the session but leave the empty group behind **forever** — nothing swept it afterwards — which kept the workspace looking occupied and its snapshot unforgettable. And the close verbs are now four separate things with four documented outcomes: closing a *window* keeps everything running, closing the last tab removes the workspace **and** its snapshot, the new **Workspace ▸ Close Workspace** (also **Close** in the launcher's Workspaces card) ends the sessions but leaves the workspace restorable, and **Close and forget** removes both — which is what the restore chooser now offers on an already-open workspace instead of a disabled button and a "close it yourself first" dead end. A deliberately empty **New Workspace** finally has an ending too: deleting it, or closing the window of one that never held a tab, releases it instead of leaving a zero-session destination behind until the next restart.

- **"Workspace saved" now means it reached the disk — and only two actions ever capture your workspace.** `runtime_state.json` was written by a function that caught every error, logged a warning, and returned as though nothing had happened: a full disk, a permission error, an antivirus lock or a failed replace produced a green *Workspace saved* confirmation for a snapshot that was never stored, and **Forget** reported success for a slot still on disk. Both now report a real failure with the existing retry wording instead of a false success, and the background autosave logs one structured error per failure streak (not one per tick) while leaving the last good file exactly where it was. Renaming a workspace also stopped being a third snapshot writer — it used to re-capture the whole workspace shape, so a cosmetic label change could freeze a half-launched or about-to-be-closed layout into the restore offer. A rename now changes the live label only, and the next autosave tick or **Save Workspace** persists it; the promise on the tin is finally literal: **the autosave timer and Save Workspace are the only two writers of workspace shape.** Alongside that, *saved manually* became durable metadata of its own rather than a side effect of who wrote the snapshot last, so a workspace you saved by hand keeps its permanent-offer pin however many times autosave refreshes it.
- **A corrupt or unrecognised `runtime_state.json` is quarantined instead of silently emptied.** An unreadable state file used to be swallowed into an empty state that the next capture overwrote for good — the evidence and every saved workspace in it were gone. The file now carries a schema version the app checks (v3; v1 and v2 files still migrate on read), every commit keeps the previous file as `runtime_state.json.bak`, and a file that cannot be parsed, or that was written by a newer GridVibe, is moved aside as `runtime_state.json.corrupt-<timestamp>` with the last-good backup loaded in its place. All of it now runs through one runtime-state store that owns the file path, the process lock, and — new — an **OS-level lock** across the whole read-modify-replace, plus a durable per-workspace revision. Two GridVibe processes sharing one state file can no longer interleave and discard each other's updates, and a close performed by one process still rejects a snapshot the other took before it, even across a restart.
- **The Source view marks what changed against `HEAD`, and clicking a mark shows the change right where it hangs.** Three pieces, one model. In a Git worktree, every line added or modified against `HEAD` carries a coloured gutter bar (green / blue), and a deletion leaves a wedge on the boundary where its lines used to be; a slim **overview column** docked beside the source paints the same marks over the whole file and doubles as the panel's scrollbar — click, drag and wheel all drive it, and clicking one of its markers jumps to that change. New with this round: the gutter marks are **buttons**. Clicking one opens a **change peek** — a compact diff of that block alone, inserted inline directly under the change with the `HEAD` lines it replaced stacked above the worktree lines that replaced them, numbered and highlighted exactly like the Diff panel. Click again, its close button, or `Escape` while focus is inside it and it collapses; a block over 200 lines renders its first 200 plus an **Open in Diff** handoff. The peek is pane state re-applied after every Source rebuild, so it survives `Ctrl+F` keystrokes, wrap toggles and Markdown folds, and it closes honestly when its block is folded away, edited over, reverted or committed out from under it — never a stale diff. Everything renders from the `git/diff?mode=head` model the pane already holds: no new endpoint, no fetch of its own, nothing mutated. The Diff panel's red/green cell tints moved into shared `--gv-diff-add-bg` / `--gv-diff-delete-bg` tokens so the peek and the panel share one palette by construction.
- **A closed workspace stays closed.** Workspace autosave read the live workspace shape and only then queued up to write `runtime_state.json`, so a tick that started moments before you closed a workspace could land *after* the close had already removed that workspace's saved slot — putting the workspace you just closed back on the restore-after-restart offer, sometimes for a shape that no longer existed. Captures are now ordered per workspace: every capture and every Forget takes a monotonic ticket before it reads anything, and a capture is dropped at commit time if a close/forget landed after its snapshot was taken. The same ordering stops an older autosave tick from overwriting a shape a later capture already stored, while an explicit **Save Workspace** still wins over an autosave that happens to finish alongside it — only closing or forgetting the workspace overrides your own save. A save that races a close of the same workspace now reports failure instead of silently re-saving it. Nothing changes for the ordinary path: autosave and Save Workspace persist exactly what they did before.
- **The test suite can no longer overwrite your saved workspaces.** `config.json` and `saved_sessions.json` were redirected to temporary files while tests ran, but `runtime_state.json` was not, so a test that exercised the real Save Workspace route wrote its fixture into the restore slot of whoever ran the suite — which then reappeared after the next restart as a workspace nobody had opened. The state file location is now overridable through `GRIDVIBE_RUNTIME_STATE_PATH`, the suite points it at a temporary directory before the app is imported, and `GRIDVIBE_TEST_MODE` makes any attempt to read or write the canonical `runtime_state.json` from a test process fail outright rather than quietly succeed.
- **A scratch session is one click away on the launcher.** **Session Source** gained a **New Session** button at the head of its toolbar, left of **Save Session**. It does exactly what **Import Session → Default session** did, minus the picker: the built-in empty preset is loaded into the form, so a throwaway setup no longer costs a dialog and a scroll past every preset you have saved. The default entry is virtual — nothing is written to `saved_sessions.json` and no saved preset is touched or overwritten. With four actions the toolbar no longer shared a row with the step title comfortably, so the **Session Source** heading now stacks its buttons underneath rather than wrapping one of them off on its own.
- **The Git sidebar's change rows now lead with the file name.** Every row in **Staged Changes** and **Changes** rendered the repository-relative path verbatim — so in the panel's narrow column the visible text was `maria/db/d…`, `models/mo…`, `yaml_db/co…`: all directory, no file (`docs/images/curent_git_unclear.png`). The one piece of information the row exists to carry was the first thing truncated away. Rows are now `name — muted directory`, the ordering an editor uses, and the directory carries an outsized flex shrink factor so it is what gets cut off first; the file name only starts to ellipsis once the directory has collapsed entirely. The full path is still on the row's `title`, and **Copy path** / **Copy relative path** / **Download file** in the right-click menu are unchanged — they read `data-explorer-copy-path`, which still holds the whole path. Two smaller changes came with it: the `M`/`A`/`?`/`D` status badge moved from the row's left edge to the right of the name, just ahead of the inline actions, so nothing sits between the pane edge and the name; and the two change lists dropped the 28px indent they inherited from the commit-history rows, where it exists to align files under their commit's graph column. History rows keep both the indent and the new name-first labelling.

- **Explorer and browser panes can now split off a terminal.** The two split controls used to be terminal-only: an explorer pane showing the exact directory you wanted a shell in offered no way to get one beside it, so you either converted the pane (losing the listing) or went back to the launcher. Both pane kinds now carry the same side-by-side and stacked controls, and both produce a *plain terminal* rather than a copy of themselves — the labels say so (**Split off a terminal beside this pane** / **below this pane**). For an explorer the new terminal starts in the directory you are currently browsing, not the one the pane was launched with, and it resolves through the same root-containment rules the pane-mode switch uses, so a path outside the configured root is refused rather than quietly opening a shell somewhere else. This works in both modes: an SSH explorer splits off an SSH terminal on the same host, port, and credentials; a Local Repo explorer or browser pane splits off a local shell relabelled with the shell it actually runs (`cmd`, `PowerShell`, `WSL (…)`) instead of inheriting the pane's `File Explorer` chrome. A browser pane's URL no longer rides along as the new shell's first command.

- **Starting a throwaway session no longer means remembering an IP — or settling for one of them.** Step 02 was pure recall: to launch anything you had to type a host, a username, a port, or a full repository path from memory, and there was no way to ask GridVibe what it already knew. Each mode button now has a caret beside it that lists the connection targets your saved sessions already use — SSH addresses under **SSH Remote**, local repository folders under **Local Repo** — deduplicated by target rather than by preset, newest first, and topped by a **Blank** entry that clears the fields the way the button always did. Picking one fills in the Step 2 fields and nothing else: the terminal rows stay at their defaults, and the launch stays *unattached* to the preset the address came from. That distinction is the point — it is a shortcut for the address, not `Import Session`, so borrowing a host does not tie you to the preset that owns it. The target list is deliberately secret-free (`GET /api/session-targets` returns hosts, ports, directories, and a `has_password` flag — never a password); the saved password is fetched from `GET /api/saved-sessions/<id>` for the one target you actually pick, so listing targets never ships every stored credential at once.
- **The default session can be launched as many times as you want.** Launching the built-in **Default Session** twice on the same host quietly replaced the first workspace instead of opening a second — and with multiple workspaces on, the second attempt was refused outright with *"already open in another workspace"*. The cause was an identity mix-up: `default-session` was sent as a saved-preset id, so every scratch launch minted the same stable group id (`saved-session-default-session`), which the launch path treats as *this preset's one group* — it replaces that group's sessions in place, and guards it against being live in two workspaces. But the built-in default is a blank *form*, not a stored preset; it owns nothing. It now carries no launch identity at all, on both sides of the wire, so every launch mints its own group and the uniqueness guard is left for the presets it was written for. Repeats are numbered instead of colliding: `10.0.0.5`, `10.0.0.5 (1)`, `10.0.0.5 (2)` — the name is checked against the live session tabs *and* the saved presets, so promoting one scratch session to a saved one makes the next launch skip past its number rather than reuse it. A saved preset still launches under its own name verbatim, and a restore still replays the name it stored — neither is renumbered.
- **A workspace you closed hours ago stops reappearing on restore.** Two faults, one symptom: a workspace nobody asked for — in testing, a one-pane explorer group left over from a throwaway preset — opened alongside the ones that were actually selected, both on a plain restore and right after clicking **Forget** on some *other* row. **(1)** The main workspace's snapshot was immortal. Emptying any other workspace forgets its shape (1.7.0 made that global, snapshot included), but that cleanup rides on the *record* being pruned, and `default`'s record is permanent by design — so it never reached the cleanup and nothing else ever cleared its slot: the capture side only overwrites a slot with a non-empty snapshot, never clears one. A group run in the main workspace once stayed on offer in the chooser forever, removable only by hand. Closing its last group (or moving that group out) now forgets its snapshot too, through a deliberately narrow rule — the close must have emptied `default` *itself*, and it must own no groups afterwards, so closing one of several tabs keeps the slot and a close in a sibling workspace never touches an unrelated empty `default`. Only explicit closes and moves take this path; a process exit does not, so restore-after-restart is exactly as before, which is the whole point of the feature. **Close all sessions** is also unchanged: like its non-default siblings, it tears down live state and keeps every snapshot. **(2)** The restore chooser threw away your selection on every re-render. Rows are built with the checkbox pre-ticked, and both **Forget** and a completed restore rebuild the list from scratch — silently re-ticking rows the user had deliberately unticked. So unticking a workspace, then forgetting a different one, quietly re-selected it, and the next **Restore** opened it. Selection now carries across renders per workspace id; only rows the render has not seen before default to ticked, and an already-live row stays unticked regardless, since it cannot be restored anyway.
- **`Alt+W` no longer opens a blank window when there is only one workspace to be in.** With a single window open the shortcut answered by opening a *second*, empty one — the opposite of a switch. The walk read `GET /api/workspaces` and treated every row as somewhere to go, but a live workspace *record* is not an open window. Two records routinely have no window: `default` is permanent and is never pruned, so launching into a new workspace leaves an empty `default` sitting in the list beside the one you are in; and **Workspace ▸ New Workspace** retains its (empty) workspace until its first tab arrives, so one created and then closed unused stays in the list for the rest of the process. Stepping onto either handed `switchToWorkspaceWindow()` a workspace with nothing to show, and it did the only thing it could — opened a window on it. `nextWorkspaceInCycle()` now walks only workspaces that still hold a session tab, which is exact rather than a heuristic: a window closes itself the moment its last tab goes (`_closeWindowAfterLastSession()`), so `group_count > 0` and "there is a window there" are the same condition. The current workspace stays in the list whether or not it is empty, so the walk keeps its place in the order, and with nowhere else to go the shortcut reports **No other workspace is open** instead of conjuring a window. **Workspace ▸ Open Workspace** is deliberately unchanged — clicking a named empty workspace to open a window on it is the point of that menu; `Alt+W` is a cycle between windows, and its ordering still comes from the same helper, so the two cannot disagree about *order*, only about which rows the cycle skips.
- **Terminal Setup now wraps its terminal cards instead of fighting the Workspaces panel for the column.** Two symptoms, one cause. With both right-column panels open, the bottom of step 03 — and with several terminal rows, whole terminal cards — was painted over by the Workspaces card below it; either panel folded on its own looked fine, which is what made it read as a fold bug. Fixing that by making the row honour the card's floor then produced the opposite complaint: expanding a terminal tile squeezed the Workspaces panel. Both come from the same two settings disagreeing — the column sized Terminal Setup's row with `1fr` (take the leftover) while the card carried a `min(520px, 64vh)` floor (never be smaller than this). A grid item taller than its track *overflows* it and does **not** push the following rows down, so whenever the leftover fell under the floor the card spilled into row 2, where a Workspaces card with its own background painted straight over it (measured in page at a 640px frame: a 105px row holding a 520px card, 403px of overlap). Neither setting survives. All three rows are now `auto`: the card wraps exactly the tiles it holds — a set of folded tiles takes only their height — and grows as one is expanded until it hits a cap of one fully expanded tile plus chrome (`min(520px, 58vh)`, down from `calc(100vh - 200px)`), after which `.rows-wrap` scrolls as it always could. Nothing claims the column's leftover space, so Workspaces gets what Terminal Setup does not need, and the column scrolls only when the two genuinely do not fit. Gone with the `1fr` row: the `terminal-setup-folded` class the fold controller put on the column and the rule it fed, which existed only to stop a folded card being stretched by that row, plus two now-inert declarations on `.terminal-card.card-folded` (a `min-height: 0` countering the deleted floor, and a `flex` shorthand on what has always been a grid item).
- **"Maximum 16 terminals allowed" from a button that stops at 8.** **Add Terminal** walks a fixed ladder of counts (1, 2, 3, 4, 6, 8 — a count is only offerable if it has a layout preset in `LAYOUT_COPY`), but both of its refusal messages quoted `max_sessions`, which is the *backend's* per-group session limit and defaults to 16. The message now names the ladder's top, which is 8 unless a lower configured `max_sessions` trims the ladder below that. The dead `selectedCount >= MAX_SESSIONS` pre-check that could never fire on a default config went with it, and the two branches that computed the next count collapsed into one — on an ascending ladder, "the first entry above the current one" already *is* `selectedCount + 1` whenever that count is offered.
- **Two follow-ups to the combined Startup Mode dropdown.** **(1)** An agent's preflight result no longer repaints the whole mode list. The status colours moved onto the combined select as `background-color` + `color`, and a native `<select>` hands both of those down to its popup — so after checking, say, Claude, the open dropdown showed **Terminal**, **Initial Command**, **File Explorer** and **Browser** in that agent's green, orange or red too, as if every mode had a CLI install state. The status now paints the control's frame only (border plus a 1px inset ring); the status *word* was already carried three other ways — the selected option's `· Installed` suffix, the preflight summary chip under the field, and the select's tooltip — none of which changed. The block's per-theme colour literals were replaced by the theme-aware `--gv-success` / `--gv-warning` / `--gv-danger` / `--gv-accent` tokens, so the two `[data-theme="light"]` override blocks are gone. **(2)** Switching a card from an agent to **Browser** no longer lands on `http://claude/`. A draft carries one `initial_command`, which in agent mode holds the agent's name, and the row builder seeded *both* the Initial Command and the Browser URL inputs from that same value — so the hidden URL box was pre-filled with `claude` and the pane launched at that host the moment the mode changed (the value is a valid hostname, so URL normalization accepted it). Each input now seeds only from its own mode; a browser field on any other kind of draft starts at the default `http://127.0.0.1:3000`, which is now one named constant rather than three copies of the literal.
- **The terminal card's agent choice now lives inline in the Startup Mode dropdown, and the card got materially shorter.** The separate Agent select is gone: the startup-mode select carries an `Agent` optgroup with one entry per registry agent (values encoded as `agent:<name>`, plus the custom entry), so one dropdown answers "what does this pane run" in a single pick — the preflight status colours and the "· Installed" suffix moved onto that combined select, and the saved-session payload keeps its separate `startup_mode`/`agent_selection` fields untouched. The auto-mode launch explanation no longer sits as a permanent paragraph inside the checkbox: it hides behind a `?` tip button (the same inline-tip pattern the Shell field uses) and updates in place when the agent changes. Vertical room got the same treatment as horizontal clipping before it: Terminal Setup keeps a floor tall enough to show one fully expanded agent-mode card even with the Workspaces panel open (the column scrolls before step 03 gets crushed), the Workspaces live list scrolls instead of growing the card without bound, and expanding a card scrolls it fully into view — pinning its top when it is taller than the panel. The native launcher window opens 10% larger (1408×924) at 90% content zoom, applied through the existing native-zoom control once the page loads, for ~20% more usable form area.
- **The launcher's Terminal Setup no longer clips its cards at narrow widths, and both right-column panels fold.** At zoomed or narrow window sizes the step-03 card grid overflowed its panel and cut the terminal cards (and their Subdirectory fields) off at the right edge (`docs/images/clipping.png`): each card is a grid that never declared a column, so its implicit `auto` track grew to the content's max-content width and the card's `overflow: hidden` cut off everything past its right edge — fold chevron, status dot, inputs, checkboxes. The cards now pin an explicit `minmax(0, 1fr)` column (and their rows and inputs carry `min-width: 0`), so the content always resolves to the width the panel gives it at any window size or zoom level. On top of that, each terminal card gained a chevron in its head that folds it down to the title row — the whole head is the click target, not just the chevron, with the title input opting out — and a collapsed card hugs its head instead of stretching to an expanded neighbour's height; and cards default to folded when three or more terminals are selected (fold state is view-only, snapshotted across the DOM rebuilds that count changes and session imports trigger, and never written into saved-session payloads). The **Terminal Setup** and **Workspaces** panels themselves fold too, from a chevron in their section heads, persisted in `localStorage` like the theme preference; a folded Terminal Setup releases its stretched `1fr` grid row so no empty hole remains. Inside each card the field stack is now a two-column flow where width allows (Subdirectory and Startup Mode share a row), with the taller conditional blocks (command, agent, shell, distro) still spanning full width. Three smaller courtesies landed alongside: the uppercase field-caption styling no longer leaks into nested check-field labels (the agent auto-mode help and the shell checkboxes read in sentence case again — a check-field is itself a `<label>`, so it inherited the caps), section-head actions now group on the card's right edge instead of `space-between` stranding the middle button mid-card, and the Subdirectory placeholder was shortened to fit the narrow cards, with the full wording moved to the input's tooltip. Also removed: the `--terminal-columns` custom property `buildTerminalRows()` set on every rebuild, which no stylesheet has ever read.

- **Opening a repository-search result now highlights the matched string, not just its line.** Clicking a hit scrolled the Source view to the line and flashed the whole row, which says *where* but not *what*: on a long line the reader still had to hunt for the term they searched for, and had nothing to double-click to carry into Ctrl+F. The exact matched substrings are now painted in the find-match yellow on the opened row, from the column ranges the backend already computes and sends with every hit — so no client-side re-matching, and a regex or whole-word search highlights exactly what the engine matched, including multiple matches on the same line. The paint goes through the CSS Custom Highlight API rather than `<mark>` wrappers, for the same reason the selection occurrence tint does: rewriting the Source DOM is what re-runs the Markdown fold pass and throws away the scroll position, and the hit has just scrolled the view somewhere specific. Its ranges detach with the row when the Source view re-renders, so the paint clears itself on the next file, tab, or find, and it is registered above the occurrence tint so the two do not fight where they overlap. Server offsets count code points and the DOM counts UTF-16 units, so a span whose text does not match is re-found on the row instead of painting the wrong characters. Browsers without the Highlight API get the line flash exactly as before. Unchanged: the hit still does *not* seed a pane-local find — it is one source location, not a second search — so nothing scrolls off to the file's own first match.
- **The Source font now applies to the Diff view too.** Picking Cascadia Code or JetBrains Mono in the appearance menu restyled the Source view and left the Diff beside it in the default Consolas stack — so a split view showed the same file in two different faces. The setting was carried by a `--source-view-font` custom property declared on `.explorer-source-view`, and the diff panel is that element's *sibling*, not its descendant, so there was nothing for it to inherit from. The diff panel now hosts the property itself and carries the same `source-font-*` class, applied by the same `applyExplorerSourceFontToElement()` on render and on every change. Both diff renderers restate the property for the same reason the source rows already did — a more specific declaration was beating the inherited value: the handwritten side-by-side fallback pinned its own Consolas stack, and Diff2Html's vendored CSS pins `.d2h-diff-table` to Menlo (overridden in `terminals.css`, not in the vendored file, so the pinned asset can still be replaced verbatim on upgrade). The commit-diff view, which has no appearance button of its own, picks up the stored preference on open. Nothing else about the setting changed: same allowlist, same `gridvibe.sourceViewFont` preference, same three persistence paths.
- **The last six text glyphs in the explorer are now SVG icons.** The Files tree's expand chevron and its open-folder and open-in-a-new-tab buttons, the Git row's open-containing-folder button, the diff commit-history expand toggle, and the Markdown section fold chevron were still drawing `▾ ▸ ↪ ↗` as button text — so they scaled with the font rather than the icon size, sat off-centre against the stroke icons beside them, and rendered differently per platform depending on which font supplied the arrow. All six now use the same stroke-style `currentColor` SVG language as the rest of the pane. The three chevrons reuse the shared `UI_CHEVRON_*` constants the repo-search groups already use; the two navigation buttons got their own icons (a folder and an external-link arrow) chosen to stay distinguishable from each other and from the Git stage `+`, which is what the two different arrow glyphs were doing before. Behaviour, hit areas, and every `title`/`aria-label` are unchanged.

Open tabs persist as paths *relative to the pane's root*, so retargeting the root leaves every one of them pointing at a file this explorer does not have. Three things were wrong and each is fixed. **(1)** The launcher carried the saved tab strip through invisibly in the row dataset, including across an edit to the row's directory; the row now records the directory its tabs belong to (`data-explorer-tabs-dir`) and drops `explorer_open_tabs`/`explorer_active_tab`/`explorer_tab_views` as soon as that no longer matches, so retargeting a pane relaunches it clean instead of with another root's tabs. **(2)** The restore opened the saved active tab and, when the fetch failed, left the pane *unattached* — no directory had been loaded, so `renderExplorerDirectoryOpenError()` fell through to replacing the whole viewer with the error text and the breadcrumb never got its clickable crumbs. The restore now opens the tab itself rather than through `activateExplorerTab()` (which reports nothing back), and on failure falls back to a directory listing — the saved Preview directory if it still exists, otherwise the root, which the session guarantees does exist. A tab whose file is genuinely gone is dropped; a tab that failed for any other reason is kept unselected so clicking it retries. **(3)** A missing path answered with the wrong shape entirely: SFTP `normalize()` resolves against the server and fails outright on a path that is not there, so paramiko's `[Errno 2] No such file` surfaced verbatim as a **500**, and the local backend called it "Explorer path is not a file". A path that was never inside the root still gets the containment error rather than becoming an existence probe, and the open-file change listener already treated 404 as stop-immediately, so a file deleted while open still parks quietly on the last good view.

- **The coding fonts the pickers name are now shipped with GridVibe.** Following on from the above: *neither* JetBrains Mono nor Cascadia Code is present on a stock Windows install (Cascadia ships inside the Windows Terminal app package, not system-wide), and both stacks end in Consolas — so picking either one, in the explorer's font menu or in App Settings' terminal font list, produced no visible change at all. That is what made Consolas look like a duplicate of JetBrains Mono: it *was* JetBrains Mono, falling back. Glyphs a face lacks still fall through to the next family in the stack, and italics are synthesized from the regular face. One knock-on: a terminal pane set to a vendored font could be measured against the fallback face and repainted with the real one, leaving its grid a fraction off, so panes re-fit once `document.fonts.ready` resolves; a pane on an installed font measures the same twice and sees nothing.
- **Wrapped diffs now wrap on both sides.** With line wrapping on, the right column reflowed inside the pane while the left column was cut off at the pane's edge — most visibly on files whose hunks sit inside a function or a class. Diff2Html renders each side as its own table, and Git's `@@ -a,b +c,d @@` header carries the enclosing section name (`@@ -120,7 +120,9 @@ def open_explorer_file(...)`) on the **left** side only — the right side gets a blank placeholder. That header's text sits directly in the `nowrap` line div with no `.d2h-code-line-ctn` to wrap inside, so it set the left table's minimum width; every row below it inherited that width, and wrapped mode's `overflow-x: hidden` (it hides the paired horizontal scrollbars, since wrapped text should not need them) clipped the overflow with nothing left to scroll it back. The block header now wraps with the code. Unwrapped mode is untouched: both sides still keep full-width lines and their own sticky scrollbars. Deliberately *not* also pinning the tables with `table-layout: fixed` — that looks like the robust belt-and-braces guard and it is not: fixed layout hands the number column an equal half of the side while the number cell's own `max-width: 4em` still holds its box at 4em, so the gutter paints 4em wide and the remainder of its column renders as a ~390 px blank gap in front of every code line on both sides (`docs/images/diff_empty_space.png`).
- **Long lines keep their intraline diff emphasis.** `maxLineLengthHighlight` was pinned at 2000 characters, below Diff2Html's own 10000 default, and that limit is all-or-nothing: a line past it renders as a plain red/green block with no darker `<ins>`/`<del>` marks on the parts that actually changed, so a one-value edit inside a long line looked like a wholesale rewrite. It bites generated SQL, migrations, seed data, and minified assets hardest — exactly the files where reading the change off the block colour alone is hopeless. The cap now tracks the vendored default. The char diff behind it is O(n·d) in the *edit distance*, not the line length, so the common case (a small edit inside a long line) stays cheap, and the diff payload is still bounded to 256 KiB / 4,000 lines before it ever reaches the renderer. Unchanged: `matchingMaxComparisons` (1500) and Diff2Html's 200-character `maxLineSizeInBlockForComparison`, which decide whether a block's deletions and insertions get *re-paired* before comparison — a block of long lines still pairs them in order.
- **Diff syntax colour is applied once instead of twice.** `renderExplorerDiffWithDiff2Html()` called `ui.highlightCode()` after `ui.draw()`, but `draw()` already highlights when the config sets `highlight: true` — so every diff was highlighted, then highlighted again over its own output, nesting a duplicate `<span class="hljs-…">` inside each span the first pass produced and doing the Highlight.js work for every line of the patch a second time. The intraline `<ins>`/`<del>` markup survived both passes, so this was invisible, but it doubled the render cost of a large diff.
- **A file you can't open can now be downloaded.** Download was reachable only from the file viewer's toolbar, which means it was reachable only for files the viewer can render — exactly the wrong set. An archive, a binary, or anything past the 10 MiB text limit never reaches editor mode, so the one control that would have got it off a remote host sat behind a view that refuses to open. **Download file** now sits in the explorer's right-click menu next to **Copy path** / **Copy relative path**, on Files-tree rows, Preview listing rows, Git **Changes** rows and pinned file tabs, and downloads the row you clicked rather than whatever the viewer happens to hold. It is the same read-only `GET /api/explorer/<id>/download` the toolbar button uses — same 100 MB cap, same root confinement, same pywebview `save_download` bridge in the native window where WebView2 drops anchor downloads — so the read-only explorer contract is untouched. It is offered only where the worktree copy is the file the row names: directory rows, deleted entries, Git rows for a deleted path, and commit-history rows (which show a past commit's version, not the worktree's) don't get the entry rather than getting one that would download the wrong bytes or fail.
- **`Alt+W` no longer dead-ends on a workspace whose terminal was left highlighted.** Cycling through three workspaces stopped at the first one holding a focused pane: every keystroke went into the terminal and the window could only be left with the mouse. Three separate faults, each enough on its own. **(1)** xterm keeps exactly *one* custom key event handler per terminal, and the clipboard wiring installed a second one — silently replacing the pass-throughs `makeTerminal` had set up. xterm then claimed `Alt+W`, sent `ESC w` to the shell, and cancelled the event with `preventDefault()` **and** `stopPropagation()`, so the page-level shortcut never ran at all. The pass-throughs and the copy/paste keys now share a single install (`attachTerminalKeyEventHandler()`), which is also what restored `Ctrl+Shift+F`'s guaranteed path to the scrollback search overlay. **(2)** Even once the key arrived, the shortcut discarded it: `Alt+W` is suppressed over editable targets, and xterm's helper textarea — the keyboard target of every focused pane — is a `<textarea>`. It no longer counts as one for this shortcut, while real inputs (search boxes, name fields, explorer controls) still block the cycle. **(3)** DOM focus survives a window switch, so a workspace left with an active pane came back with that pane focused again. Leaving a workspace now parks the window with nothing selected — both when GridVibe makes the switch (the keybind, **Workspace ▸ Open Workspace**, a session moved to another workspace, a new workspace window, all through one `switchToWorkspaceWindow()` wrapper) and when you simply click another window, which on a second screen is the usual way. The window-blur drop is deferred a tick and checks `document.hasFocus()`, so clicking into a browser pane's iframe is not mistaken for leaving. `Alt+1`–`Alt+9` still go to the shell while a pane is focused, since `Alt`+digit is a legitimate terminal binding; they work as tab switches again as soon as the pane is no longer focused, which is now the state any backgrounded workspace returns in.
- **Selecting a word in the explorer's Source view now tints its other occurrences.** Double-click a word — or drag-select any single-line snippet — and every other occurrence in the open file lights up, the way an editor does. Until now the only way to see them was Ctrl+F, which answered the question but paid for it: it re-rendered the source, so the view snapped back to the file's first match and, in Markdown, unfolded the whole document. The occurrence tint never rewrites the source DOM at all — it is painted with the CSS Custom Highlight API, so folds stay folded, the scroll position stays put, and the selection you just made survives. A selection that is a bare identifier matches whole words only (double-clicking `id` does not light up every `width`), anything else matches as a substring; matching is case-insensitive like the find widget, capped at 500 occurrences, and debounced 90 ms so a drag-select does not rescan on every mouse move. The selected text itself keeps the browser's own selection paint rather than being tinted twice. Browsers without the Highlight API (it needs Chromium 105+/WebView2, Firefox 140+ or Safari 17.2+) simply see no tint — nothing errors, and the find widget stays the explicit fallback.
- **A find seeded from a selection opens on the match you were looking at.** Ctrl+F over a highlighted word used to seed the query and then activate match 1 of N, throwing the Source view back to the top of the file; it now activates the first match at or after the caret's line. The same anchor applies to repo-search hits: clicking a result seeds the in-file find on the line the hit is on instead of scrolling away from it. The seek is consumed once, so paging with Enter/⇧Enter afterwards is unaffected, and typing in the find box is its own starting point.
- **A find no longer unfolds a whole Markdown source.** Collapsed sections were disabled outright while a search was active, so every Ctrl+F threw away the fold state a long document had been read down into. Only the sections that actually contain a match are opened now, and only when a result set is first computed — so collapsing a section during a live find sticks instead of springing back open, and every other fold is left exactly as it was.

The tree refresh is bounded to the 16 shallowest visible nodes because each one costs an `/entries` (one `git status` on a subtree); deeper expansions keep today's manual-refresh behaviour. `_explorerGitContext` — until now written by four call sites and read by none — is what gates the consumer, and the image viewer stops clearing it, since it describes the repository the *pane* is rooted in, not the shown file.   - Clicking the microphone with an unavailable backend now shows the reason as a toast (and marks the button), instead of hiding it in a `title` tooltip where nothing appeared to happen.
