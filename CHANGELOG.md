# Changelog

All notable changes to GridVibe will be documented in this file.

## Unreleased

- **The Files tree's ↗ opens a background tab instead of jumping to it.** The control is how you queue up the files you are about to need, but it also switched the viewer to each one, so opening three files while reading a fourth meant three interruptions and a trip back. It now only adds the tab: the viewer keeps showing whatever you were reading, and clicking ↗ on a path that already has a tab scrolls that tab into view and pulses it for 1.2 s rather than pulling focus to it — the repeated click still answers, it just answers in the strip. That flash reuses the locate-in-tree pulse's shape (`--t-accent` outline, self-clearing timeout), and matches the tab by dataset rather than an attribute selector, since a tab id is a file path and not safe to interpolate into a CSS selector. Nothing is fetched at open time either — the new tab carries just its path, and `activateExplorerTab()` loads the file on the first click, the same lazy path a tab restored from a session snapshot already takes, so queueing files costs no requests. The tab does join the persisted tab set immediately, and it inherits the Git badge from the tree row that opened it (`explorerTreeEntryForPath()`), so a background-opened new or modified file is badged like a foreground-opened one instead of waiting for a sidebar sync. The deduplication, the 12-tab cap, and its never-evict-the-active-tab rule are unchanged: pinned-tab creation moved into one `explorerEnsurePinnedTab()` helper that `explorerAssignOpenTab()` now calls, so the focusing and non-focusing paths cannot drift apart. **Double-clicking the Preview tab to pin its file now opens in the background too**, which makes it a bookmark rather than a jump: the viewer stays on Preview showing the same file, and a path that already has a pinned tab gets the same flash instead of being activated. It keeps carrying the Preview tab's view mode, scroll, zoom, wrap, and Git badge onto the new tab, so the first click on it restores exactly what you were looking at — but it no longer hands the rendered DOM over (`_explorerRenderedTabId` stays on Preview, whose DOM is still what the viewer shows), because the new tab is unloaded like any other background tab. Markdown links still focus what they open — a link is navigation, not queueing. **Closing the tab you are reading now falls back to Preview rather than to the pinned tab beside it.** The neighbour is an accident of open order, so landing there meant reading a file you did not ask for — and now that tabs load lazily, paying a fetch for it; Preview is the pane's own navigation surface and comes back holding the listing or file it already had. `closeExplorerTab()` re-points and renders directly instead of going through `activateExplorerTab()`, whose already-shown guard would short-circuit in the one state where the viewer holds Preview while a pinned tab is active (a pinned tab whose file failed to open over a directory listing) and leave the closed tab sitting in the strip. Closing a background tab still touches nothing but the strip, and a dirty edit in the closed tab is still confirmed first.
- **`Alt+W` swaps workspace windows, and the Move submenu says which session it moves.** Two small findings from using multi-workspace mode. **(1)** Switching windows was a three-step trip through **Workspace ▸ Open Workspace ▸ <name>**, next to session tabs that have had `Alt+1`–`Alt+9` all along. `Alt+W` now walks the live workspaces in list order and `Alt+Shift+W` walks back, reading the *same* list as the menu through one helper (`nextWorkspaceInCycle()` in `workspaces.js`), so the shortcut and the menu can never disagree about what the next workspace is. Opening a workspace that already has a window only focuses it, so a repeated press is a plain cycle and never opens a second window; an in-flight guard keeps a held key from queueing a burst of opens. It is gated on the mode, ignores editable targets like every other page shortcut, and is announced next to the menu entry it replaces. xterm gets an explicit pass-through for it, since it would otherwise send `ESC w` to the shell. **(2)** **Move Session to Workspace** never said *which* session — it acts on the active tab, but read as if it were about to move whatever the destination entry named. The heading now carries the active tab's name in parentheses and the list's `aria-label` names it too, both refreshed each time the menu opens.
- **Multiple workspaces is a switch on the launcher, not a checkbox in a dialog.** A finding from testing (`docs/r&d/todos.txt`): the mode decides whether *every* launch can open its own window, and it was a checkbox two clicks deep in **App Settings**, under the auto-save slider — a feature-sized decision filed as a preference. The launcher's **Workspaces** card (step 04) now always renders and leads with a full-width switch that states the mode it is in, so the way into the feature is on screen while the feature is still off; the card's live-workspace list stays server-gated, since with the mode off there is nothing to list. The behaviour is untouched: turning it off still confirms in page what it will close, closes every workspace except the main one, tells the other windows, and reloads. What moved is where the decision is made and who owns the write — the policy already lived in `workspaces.js` and is now reached through one entry point (`setMultiWorkspaceEnabled`) that persists `multi_workspace_enabled` **alone**. The App Settings dialog no longer renders, collects, or sends the key at all, so saving an unrelated setting there can no longer carry a stale mode along with it (an omitted key keeps whatever the server has).
- **Explorer file tabs answer the two questions you ask of a tab: where is this, and copy its path.** Two findings from testing (`docs/r&d/todos.txt`). **(1)** Right-clicking an open file tab fell through to the browser's own menu — the Files tree and the Git rows had offered **Copy path** / **Copy relative path** since ISSUE-2026-028, but the tab strip, which is where the file you are actually reading is named, had nothing. A pinned tab now carries the same `data-explorer-copy-path` hook and opens the same in-page menu. It deliberately exposes no context *kind*, so the tab menu stays copy-only — none of the filesystem mutations the tree rows offer appear on it, and copying is a read, so the read-only contract is untouched. The permanent Preview tab keeps the native menu, as before. **(2)** Double-clicking a pinned tab now locates its file in the **Files** tree: the same ancestor expansion a tab *switch* already performs, plus a scroll into view and a brief accent flash on the row. Switching to a tab reveals its file, but a tab you are already on had no way to re-run that — after scrolling the tree elsewhere, the open file was simply lost in it. If the Files panel is closed, the gesture opens it (there is nothing to point at otherwise) and the reveal waits for it, so the panel's own initial load cannot race the expansion. The Preview tab's double-click still pins the file it is showing, and locating never re-opens or re-fetches anything.
- **A workspace window no longer outlives its workspace.** Two more findings from testing (`docs/r&d/todos.txt`). **(1)** Closing the last session correctly removed the workspace everywhere — and left its window on screen showing *Load error: Workspace not found* over a tab that no longer existed, with no way back (`docs/images/zombie_workspace_window.png`). Removing the workspace made the very reload the window needed impossible, so the window sat on the error. Workspace-scoped requests now mark that one case machine-readably, and a window whose workspace is gone closes itself — whether it emptied the workspace, its last pane closed, or another window pulled its last tab away. A browser tab you opened by hand cannot close itself, so it falls back to a plain empty state instead of the error. **(2)** In **Workspace ▸ Open Workspace**, hovering the checked current workspace showed an hourglass cursor, as if it were about to become clickable. Menu items that are unavailable rather than busy now use the normal cursor and drop the hover highlight.
- **Multi-workspace dialogs are clickable, and an emptied workspace is really gone.** Five more findings from testing (`docs/r&d/todos.txt`). **(1, 3)** The **Forget** confirmation and the "Turn off multiple workspaces?" confirmation were painted *behind* the dialogs that asked for them — the restore chooser and App Settings — so neither could be clicked without closing the dialog first. Both pages stack their own dialogs and share the App Settings one, so the top of the stack was decided by document order; the confirm and workspace-name dialogs are always the answer to something already open, so they now lead the stack outright. **(2)** With the flag on, **View Active Terminals** could only ever name one of the live workspaces while sitting next to the Workspaces card that lists them all with their own **Open** buttons — it is hidden in that mode instead. **(4)** Saving a workspace or a session left its confirmation in the window chrome permanently: the message borrows the session line, which is otherwise only rewritten when you switch tabs, so with a single tab open nothing ever took it back. It now clears itself. **(5)** Closing the last session of a workspace removed it from the launcher's live list but left it in **Reopen saved…**, where reopening it resurrected a workspace you had just emptied. Emptying a non-default workspace — by closing its last tab or moving it out — now removes it globally, snapshot included. The permanent main workspace is unaffected, and leaving multi-workspace mode still preserves everything auto-save or **Save Workspace** already captured.
- **Multi-workspace can be switched on and off from App Settings, and the launcher makes sense once it is on.** Six findings from testing Stages 1–4 (`docs/r&d/todos.txt`). **(1)** `workspace.multi_workspace_enabled` had no control at all — it could only be changed by hand-editing `config.json` and restarting. It is now a **Multiple workspaces** checkbox under the auto-save interval that applies immediately: every open window re-renders into the new mode, and switching it *off* first confirms in page, then closes every workspace except the main one (`POST /api/workspaces/close-extra`) so no live shell is left where no window can reach it. Nothing is snapshotted during that teardown — what auto-save or an explicit **Save Workspace** already captured is what stays restorable. **(2)** With the flag on, the launcher was unusable: the saved-workspace chooser was an inline panel above the grid, and because `.card` sets `min-height: 0` the `1fr` row it squeezed collapsed the **Terminal Setup** card to a clipped header strip (`docs/images/launcher_display_broken.png`). The chooser is now a dialog, the right column declares its third row, and both content cards have a height floor so the column scrolls instead of collapsing. **(3)** The launch destination was a `<select>` in a separate card with no visible link to the Launch button; it is now built into the button — the CTA names its destination and a caret opens an in-page picker of live workspaces plus **New workspace…**. The launcher's workspace lists also stay fresh while the app runs: opening or closing a tab, moving one, and renaming a workspace all reach it (the launcher has no Socket.IO connection, so workspace windows relay their room events over a broadcast channel — no polling). **(4)** **View Active Terminals** always opened the main workspace; with the flag on it is now hidden entirely, because the Workspaces card lists every live workspace with its own **Open** button. **(5)** The **Saved workspaces (N)** button was indistinguishable from the live-workspace list beside it — it is now **Reopen saved… (N)** inside the Workspaces card, next to the live list it is *not*. **(6)** A workspace window did not say which workspace it was; the name now leads the session line and the window title. Fixed along the way: a window reacted to its own broadcast (a `BroadcastChannel` does not deliver to the object that posted, but does deliver to other channel objects in the same document), so the launcher reloaded itself mid-teardown and the workspaces it was closing survived.
- **Multiple live workspaces, one window each — Stages 3 and 4 of `docs/multi_workspace_implementation_plan_2026-07-30.md`.** Still opt-in behind `workspace.multi_workspace_enabled` (default `false`). The launcher gains a destination picker on the Launch button itself (an existing workspace or a new one, with an optional name) and a live-workspace list with Open; every session window gains **Workspace ▸ New / Rename / Open Workspace ▸ / Move Session to Workspace ▸ / Close Workspace Window**, plus a right-click **Move to…** on any session tab. A move changes ownership and ordering only — terminal sessions keep their ids, processes, SSH connections, scrollback, and per-session Socket.IO rooms — and both affected windows update from one room-scoped event while unrelated workspaces get nothing. A saved preset stays live in at most one workspace: launching it elsewhere returns a structured `409` and the UI offers **Open it** / **Move it here**, resolved *before* anything is torn down. Closing a workspace window leaves its sessions running and reopenable; moving the last tab out closes the emptied source window; a workspace you create deliberately empty is retained until its first tab arrives.
- **Restore is now server-side and credential-safe, closing ISSUE-2026-037.** The launcher's single restore banner becomes a chooser: one row per saved workspace with counts, age, and a disabled state with the reason. **Restore** and **Forget** are per row (Forget deletes the *snapshot* only — saved sessions are never touched, and it is refused while that workspace is live), **Not now** is dialog-level and loses nothing, and a **Reopen saved… (N)** entry reopens the chooser mid-session. `POST /api/runtime-state/restore` loads the password-free slot, resolves each referenced preset and its credential in-process, and relaunches through the *same* launch service `POST /api/sessions` uses — the JavaScript replay path is gone, so no decrypted password reaches the browser. The launch route's request-body log is redacted, and the response says **relaunch started** rather than claiming a connection. A deleted preset, a changed pane count, a missing directory, an already-live workspace, or a partly failing workspace each degrade to a per-group result instead of a failed restore.
- **New `web/workspaces.py`, `web/static/js/workspaces.js`, and `web/static/css/workspaces.css`.** The ~210-line `POST /api/sessions` body moved out of `web/api.py` into the shared launch service, and the window-dispatch code that was inlined three times in `launcher.js` now has one implementation. Automatic snapshot slots are capped at the twelve most recent (oldest-first); an explicit **Save Workspace** is never evicted.

- **The Preview directory listing and the Files tree keep up with the repository too, and a promoted tab keeps its Git badge (§15 of `docs/r&d/planed/done/explorer_git_change_listener_plan_2026-07-30.md`).** The change listener refreshed the Git sidebar and the open file but deliberately left the two surfaces the user actually clicks in alone (the plan's D7 asymmetry), so a file created or edited outside GridVibe showed up in **Changes** while the listing and the tree beside it stayed stale until a manual Refresh — no new row, no `?`, no `M`. `explorer-git-watch.js` gains a second consumer of the *same* `GET /api/explorer/<id>/git/state` poll, with its own baseline, so a pane with a sidebar, a listing and a tree open still makes one request per interval. A changed revision applies through one new door, `refreshExplorerFilesystemSurfacesQuiet()` in `explorer-viewer.js`, which re-lists the browsed directory and the visible tree nodes into scratch state and swaps them in a single render — never through `loadExplorerPane`/`reloadExplorerTree`, which reset scroll, tabs and the Find query, and never emptying the tree panel into `Loading...` first. The re-listed entries are hashed against what is on screen, so a change *outside* the browsed directory costs one fetch and zero repaints, and the apply is deferred (never dropped) while a context menu or modal is open, a pointer is down, focus is inside either surface, or the user is reading one of them scrolled away from the top. It carries the Git revision as its signal, so the listing picks a file up exactly when Git itself would report it: a non-repository root never polls for this, and an ignored file waits for a manual Refresh. The tree refresh is bounded to the 16 shallowest visible nodes because each one costs an `/entries` (one `git status` on a subtree); deeper expansions keep today's manual-refresh behaviour. `_explorerGitContext` — until now written by four call sites and read by none — is what gates the consumer, and the image viewer stops clearing it, since it describes the repository the *pane* is rooted in, not the shown file. Separately, double-clicking the Preview tab to pin the file it is showing created the new tab without a Git badge: `promoteExplorerPreviewTab()` copied the view mode, zoom and wrap state across but not `git`, so a brand-new file lost its `?` (and a modified one its `M`) until something re-opened the file or the sidebar synced — the promoted tab now inherits it.

## 1.6.0 - 2026-07-30

- **The pane Clear button no longer types `cls` at a Linux or macOS shell.** Clearing a pane wipes the xterm buffer and the replay buffer, then types the shell's own clear command so the shell's scrollback goes too. `getTerminalClearCommand()` in `terminals.js` picked that command from the pane's shell flags alone: a local ("wsl" mode) pane with neither `use_powershell` nor `use_wsl` set was assumed to be `cmd.exe` and got `cls` — but those flags are forced to `false` on a non-Windows host (`web/api.py`), where the local pane is bash/zsh, so on a Linux host every Clear answered with `Command 'cls' not found, but there are 21 similar ones` (`docs/r&d/ubuntu_problems.PNG`). The default-shell case now consults the host, reusing the same `LOCAL_SHELL_MODES_AVAILABLE` flag (via `localShellModesAvailable()`) that already gates the header's shell picker, so it stays a single source of truth for "this host has Windows shells". PowerShell panes still get `cls`, WSL panes and SSH panes still get `clear`, and Windows local panes are unchanged.
- **The open Explorer file now refreshes itself too, and an emptied diff no longer strands the viewer (§14 of `docs/r&d/planed/done/explorer_git_change_listener_plan_2026-07-30.md`).** The Git change listener refreshed the sidebar but deliberately never touched the viewer, so a file changed outside GridVibe stayed stale in the tab the user was actually looking at — while the same file in an *inactive* tab looked correct, because switching to it re-fetched. The listener (`web/static/js/explorer-git-watch.js`) now runs a second per-pane check on the same scheduler against a new endpoint, `GET /api/explorer/<id>/file/state?path=…&known=…`, which answers with `{"path", "revision", "changed"}` and `Cache-Control: no-store` from one `stat` — no read, no Markdown render, no `git status`. Every `/file` GET and successful `PUT` already carries the same token as `state_revision`, so there is no priming round trip and a GridVibe write is never mistaken for an external one. A changed token re-reads the file through one new helper, `refreshExplorerOpenFileQuiet()`, which prefers the in-place update so scroll position, view mode, search query and the tab strip all survive. **The in-place editor is an absolute gate**: while a file is open for editing the check does not run at all, and drift is still reported by the editor's existing save-conflict bar. The check also skips views with nothing to re-read (directory listings, the empty viewer, images, commit diffs), defers the apply while a Find box is focused, a selection is live in the viewer, or a menu/modal/pointer-drag is in progress, shares the Git check's adaptive floor, churn damper and backoff ladder, and suspends silently after repeated failures (a deleted or moved file stops it immediately) until any fresh load re-arms it. Separately, undoing the last hunk — or discarding a file's changes from the sidebar — left the viewer stuck, for two independent reasons. `setExplorerFileView()`'s guard for a missing diff panel (`normalizedMode === 'diff' && diffPanel ? 'diff' : normalizedMode`) resolved to `'diff'` either way, so once the discard rebuilt the viewer *without* a diff panel, restoring the captured "Diff was active" scroll state hid the source **and** preview panels and left a completely blank viewer under a live header; view selection now resolves onto a panel that actually exists, preferring the request, then the sticky source/preview preference, then whatever is left. And when the file's Git status stays non-clean — a partially staged file whose staged version survives the discard — the in-place refresh keeps an empty Diff panel mounted, so an emptied non-commit diff now falls back to the file's own content view and hides the pointless Diff toggle until a later load finds a patch again. Finally, a tab showing no file no longer carries a Git badge: viewing a modified file in the Preview tab and navigating back to a directory listing used to leave a stale `M` on the tab for the whole directory. Known limitation: SFTP reports whole-second mtimes, so a same-second remote edit that leaves the byte size unchanged waits for the next change or a manual Refresh.
- **The Explorer Git sidebar now updates itself when the repository changes underneath it (`docs/r&d/planed/done/explorer_git_change_listener_plan_2026-07-30.md`).** While a Git sidebar is open and the page is visible, a page-level scheduler (`web/static/js/explorer-git-watch.js`) polls a new cheap endpoint, `GET /api/explorer/<id>/git/state?known=<revision>`, which answers with a ~60-byte `{"revision", "changed"}` body and `Cache-Control: no-store`. The revision is a 16-hex SHA-256 token over exactly what the sidebar renders — branch, HEAD, ahead/behind, and every visible changed path with its index/worktree columns — computed in `web/explorer.py` from the same `_get_git_repo_state()` the full summary now builds on, so "revision changed" and "the sidebar would look different" cannot drift apart; every existing `/git/repo` and mutating Git route response carries the baseline for free. An unchanged poll costs one `git status` (locks-free, pooled on SSH) and causes zero DOM writes, zero refetches and zero log lines (the werkzeug poll filter now covers the route's `2xx` lines; failures stay visible). A changed poll quietly refetches `/git/repo` and swaps the panel in place with scroll/focus preserved, tab badges re-rendering only when the badge map actually changed — and the apply is **deferred**, never dropped, while the user is typing a commit message, mid-IME-composition, holding a context menu or modal open, dragging, or reading a scrolled panel. The interval self-throttles (5 s local / 10 s SSH base, a 6×-duration adaptive floor, a churn damper that doubles to a 60 s cap while a build or agent keeps rewriting files, 10/20/30 s failure backoff, and a silent suspend after 5 consecutive failures with one muted "Live updates paused — use Refresh" line). Closing the sidebar, hiding the page, or switching session-group tabs stops all Git commands for the affected panes; the listener never touches the file viewer, the editor buffer, or the directory listing.
- **The Explorer context menu can rename an entry.** Right-clicking a file or folder in the Files tree or the Preview listing now offers **Rename…** beside **Delete…**, completing the menu's mutation set. It reuses the create dialog — one shared in-page name dialog (`explorerNameModal`) now serves New file, New folder, and Rename, pre-filled and selected with the current name, `Enter` to submit and `Escape` to cancel, with no browser prompts. `POST /api/explorer/<id>/rename` is the same no-replace `rename(2)` the move route uses, applied inside the entry's *own* parent instead of a new one, so it is atomic, needs no pre-scan or byte limit, preserves the inode, permission bits, mtimes, and nested links, and reports `mutated: false` on every failure — Retry is always safe. The new leaf goes through the create route's exact-name validation (one segment, no NUL/separators/dot names/drive shapes, ≤255 characters, no `.git`), and the policy additionally refuses an unchanged name, a name already taken by any sibling, links and special entries, and anything at or under a `.git` path; it never relocates the entry, so `.git` cannot be renamed out from under its worktree. Root/entry revisions and the namespaced ancestor-aware claims coordinate a rename with in-flight saves, copies, moves, and deletes across panes on the same root, on both the local and SFTP backends. A successful rename retargets open tabs, the current directory/file (including the open file's display name), expanded tree paths, and a dirty editor buffer onto the new path — the revision is unchanged, so a pending save stays valid — then refreshes Preview, Files, and Git and highlights the result. Collisions and validation errors stay correctable inside the dialog; overwrite-on-rename, multi-select rename, and `git mv` integration remain out of scope.
- **Explorer New file/New folder and Cut/Move are now implemented together.** The Files tree and Preview directory listing expose **New file…**, **New folder…**, **Copy**, **Cut**, and context-aware Paste/Move actions, including blank-space creation for the root and empty directories. Creation uses a reusable in-page name dialog (no browser prompts), keeps correctable validation/collision errors inline, and exclusively creates the exact requested empty entry on both local and SFTP backends — no overwrite, truncation, or automatic suffix. Cut uses the same session/root-scoped clipboard as Copy; Paste then calls a dedicated same-root no-replace move route, clears a successful cut, refuses collisions/self-nesting/`.git`/cross-device moves, and never degrades into a partial copy/delete. Root/entry revisions and ancestor-aware claims coordinate create/move with save/copy/delete without holding locks during I/O. A successful move retargets open tabs, the current directory/file, expanded tree paths, and a dirty editor buffer to the new path while preserving its revision; creation and moves refresh Preview, Files, and Git and highlight the result. The bounded write contract, README, agent guidance, and both 2026-07-29 proposals now describe what shipped.
- **A Local Repo pane can change its shell on the fly (`web/static/js/terminal-shell.js`).** Switching a cmd pane to PowerShell or WSL used to mean closing it and relaunching from the launcher. The pane header's reset button is now a dropdown on local terminal panes: **Reset view** keeps its old one-click behaviour at the top, and a **Shell** section lists **Command Prompt**, **PowerShell**, **WSL** (default distro) and one entry per distro detected through the existing `/api/wsl-distros` route (fetched once per window on first open, with a retry row when detection fails). Picking one calls the new `POST /api/sessions/<id>/shell`, which flips `use_wsl`/`use_powershell`/`distribution`, relabels the pane, closes the old shell and reconnects the same session in place — the pane keeps its slot, title, startup command and startup mode, so an agent pane simply replays its command under the new shell. The pane restarts in the directory the old shell was actually in: the endpoint reuses the cwd probe that explorer mode switching already relies on (it returns Windows-form paths even for WSL panes, so `wsl --cd` translation stays the connector's job) and falls back to the pane's stored directory when the probe misses. Re-selecting the shell a pane already runs is a no-op rather than a restart, so clicking the ticked entry never kills a live shell. Offered on Windows hosts only (`LOCAL_SHELL_MODES_AVAILABLE`, mirroring the launcher's shell checkboxes); SSH, explorer, and browser panes keep the plain one-click reset button. The shell family precedence now lives in one place (`_local_shell_kind()` in `web/terminal_io.py`, used by both the connector and the new route). The switched shell also survives being saved: the restart-restore snapshot already recorded the three fields, but `_merge_workspace_session_config()` did not, so **Save Session** / **Save All Sessions** on a workspace launched from a saved preset silently re-saved the shell the *launcher* had configured — switch a WSL pane to PowerShell, save, and the preset still said WSL (and vice versa). The merge now carries `use_wsl`/`use_powershell`/`distribution` from the live pane for terminal and agent panes on Local Repo presets; explorer and browser panes have no shell, so their configured flags stand, and SSH presets are untouched.

## 1.5.0 - 2026-07-29

- **The Files-tree fold arrow no longer navigates, and unstaged diffs can undo a whole block of changes.** Two explorer quality-of-life fixes. (1) A directory row's fold arrow is now its own button that only expands or collapses; browsing the tree while reading a file no longer throws the Preview tab out of that file. Clicking the directory *name* still browses it in Preview (and expands it, never collapsing — that stays the arrow's job), so opening a target is exactly the set of clicks that look like opening a target: a file name or a folder name. (2) The per-line diff undo gained a block-level sibling: hovering any run of consecutive changed lines — a "paragraph" of the diff, ended by the first context line — reveals an **Undo block (n)** pill on the run's first row that reverts the whole run in a single save, instead of n confirmations for one edit. Blocks are parsed from the patch itself (a pure insertion, a pure deletion, and a replacement are all one block), and the undo is a single splice guarded by *every* worktree line the block expects still matching, so a stale diff refuses rather than corrupting the file. It shares the per-line undo's contract exactly: same eligibility rules (editable, complete, unstaged-only worktree diffs), same in-page confirmation, and the same root-confined revision-guarded text-save route — no new endpoint and no Git patch application. Single-line changes keep only their gutter button, since a pill there would say the same thing twice.
- **Explorer tabs now stay in sync with editor and Git state, and unstaged diffs can undo one line safely.** The blue unsaved dot is cleared immediately on Save, Cancel, confirmed discard, and conflict reload instead of lingering until the next tab switch. Open file tabs show the same `?`/`M`/`D`-style marker as the Git sidebar when that path has an unstaged worktree change; staged-only changes stay unmarked. Editable, complete worktree diffs expose a gutter undo control for each added, removed, or replaced line whether the file was opened from **Changes** or directly in its own tab (the direct tab's `HEAD` diff is eligible only while its index is clean, when it is identical to the worktree diff). Undo confirms in-page and writes through the existing root-confined, revision-guarded text-save route, so staged content is preserved and a concurrent disk change conflicts instead of being overwritten. Commit, staged, partially staged/combined, truncated, non-editable, and newline-ambiguous diffs remain read-only.
- **The explorer Source view wraps long lines too, under the same per-tab toggle.** The wrap button used to appear only for Markdown Preview and Git Diff; it is now shown for every open file and applies to whichever of the three views is active, so Source is no longer the one view that could only scroll sideways. Everything else matches the existing behaviour exactly: wrapping is **per tab** (turning it off for one file leaves every other open tab alone), it defaults **on**, and only the opt-out persists — `wrap_source` is written as `false` beside `wrap_preview`/`wrap_diff` and bounded server-side in `_normalize_explorer_tab_views()`, so tabs saved before this restore wrapped. Unwrapped Source keeps today's one-row-per-line layout and horizontal scroll; wrapped Source reflows the code column inside the pane while each line's number stays pinned to the line it belongs to. The in-place text editor follows the same per-tab flag (via the textarea's `soft`/`off` wrap — never `hard`, which would rewrite the saved bytes), so the wrap button stays live while editing and is no longer dimmed with the rest of the edit-mode chrome.
- **A restored workspace reopens on the session group you were working in.** The snapshot recorded the groups but not which one was in front, so a restore always landed on whichever group happened to be created last — with several groups saved, never the one you left. Slots now carry `active_group_id`, and both writers fill it: **Save Workspace** names the saving window's own group, and the **autosave timer** — which has no window to ask — uses a hint the session window reports through `POST /api/session-groups/active` whenever its front group changes (a user action, not a poll; `syncLocationToGroup()` is the single choke point, so a switch, a launch, and the initial load all report). The hint is validated at every step: an unknown id leaves the standing one alone, a closed group clears it, a capture keeps it only if it names a group that capture actually stored, and `load_restorable_workspace()` re-checks it against the slot's own groups. Because restored groups are minted with fresh ids, the launcher resolves the saved id to the group its replay created and opens the workspace on that (`?group=…`, or `open_session_window()` in native mode — a restore skips the plain `focus_session_window()` path, which deliberately never changes the window's URL). Nothing recorded, nothing changed: the restore falls back to today's behavior.
- **Markdown Preview and Git Diff wrap long lines by default, per explorer tab.** A wrap button appears only while either view is active. Wrapping is **per tab**, exactly like the editor zoom beside it: each tab keeps its own Preview and Diff flags, so turning it off for one file does not reflow every other open tab, and the flags save and restore with the session. Both default **on** — a wrapped view never hides content off to the right — so what is tracked and persisted is the *opt-out* (`wrap_preview`/`wrap_diff` are written only as `false`, bounded server-side in `_normalize_explorer_tab_views()`); an absent flag means wrapped, which is also what every tab saved before wrapping existed restores as. Pinning the Preview tab carries its wrapping onto the new pinned tab, as it already does for zoom and view mode. Markdown wrapping expands the old `46rem` reading measure to the full explorer width and safely breaks long URLs/table cells; preview paragraphs and list items now use justified inter-word alignment while code, tables, and diagrams remain left-aligned. Diff wrapping keeps Diff2Html's syntax and bright intraline red/green emphasis, wraps inside its fixed-width code cells, and synchronizes paired row heights around the `4em` line-number tracks so neither side nor the middle gutter drifts. With wrapping off, the existing independent horizontal scrollbars are unchanged.
- **Importing a saved session with a browser pane no longer opens a shell that runs the URL as a command.** `buildSavedSessionLaunchPayload()` in `terminals.js` — the path behind **Sessions... → Import Session** and the workspace tab bar — resolved a pane's startup mode with a ternary that only knew `explorer` and `agent`, so a `browser` pane fell through to `terminal`. It then forwarded the pane's `initial_command` (its URL) with `initial_command_mode: 'command'`, and the backend obligingly launched a local `cmd` pane and typed `http://127.0.0.1:5050/` at the prompt (`'http:' is not recognized as an internal or external command`). The launcher page's own payload builder handled `browser` correctly, which is why the failure looked intermittent — it depended on where you launched from. Both builders now resolve the mode from `startup_mode` *or* `initial_command_mode`, and `use_wsl`/`use_powershell` are cleared for browser panes as they already were for explorer panes.
- **Browser panes are tabbed (`web/static/js/browser-pane.js`).** A pane now carries up to 8 tabs — a strip above the URL bar with per-tab close, drag-to-reorder (same interaction as the session and explorer tab strips), and a **+** button that opens a blank tab at the default URL — each backed by its own long-lived `<iframe>`, so neither switching nor reordering tabs reloads the app you are testing. The active tab's URL stays mirrored into the session's `initial_command`, so every existing single-URL reader (launch, reload, external **Open**, `_normalize_browser_url`) is unchanged. Same-origin frames get their `window.open` and `target="_blank"` clicks captured into new pane tabs, which is what makes previewing GridVibe *inside* GridVibe work: the launcher's `window.open('/terminals')` now lands in a second tab instead of escaping to the OS browser. Cross-origin frames cannot be instrumented by any page, so those still open externally. Two rules keep that capture from running away: a **named** window target (`window.open(url, 'gridvibe-sessions')`) reuses the tab already opened under that name instead of stacking a new one per click — `_self`/`_top`/`_parent` stay native — and a GridVibe page that is itself inside a browser pane renders no browser frames of its own, showing a *Nested preview disabled* notice instead. Without that guard a pane showing GridVibe re-embedded the same workspace, including the pane doing the embedding, so every render spawned the next level without end.
- **Saving a browser pane now saves its tabs.** Save Workspace previously discarded live navigation on purpose and re-pinned the pane to its configured URL (or the product default), so even the single current URL was lost. `_merge_workspace_session_config()` now persists the whole live strip, and `browser_tabs` + `browser_active_tab` flow through every place explorer tab state already does: saved presets (`saved_sessions.json`, bounded and re-validated on read), the restart-restore snapshot (`runtime_state.json`), and the in-memory snapshot that survives a sibling pane closing. Presets written before tabs existed upgrade to a one-tab strip on read, and a pane leaving browser mode clears its strip. `POST /api/sessions/<id>/mode` gained optional `tabs`/`active_tab` so the whole surface still needs no new route; blank or non-HTTP(S) tab entries are dropped rather than silently replaced by the default URL.
- **Explorer copy, paste, and permanent delete (`docs/explorer_copy_paste_delete_plan_2026-07-28.md`).** Files and folders in both the Files tree and Preview listing now share one accessible in-page context menu: a one-entry, session/root-scoped clipboard, disabled **Paste — nothing copied** state, unchanged absolute/relative path copying, and danger-styled confirmed delete. Two same-origin-guarded routes share one local/SFTP policy (`web/explorer_fs.py`): parent-then-leaf resolution never dereferences a deleted link, copied trees reject links/special entries, copy streams in 1 MiB chunks under entry/depth/byte caps, atomic exclusive reservation guarantees no overwrite and allocates extension-aware `-Copy` names, recursive delete protects the root and `.git` and quarantines before depth-first removal where supported, and every error states whether retry is safe. Entry/root revisions prevent stale actions, while namespaced ancestor-aware claims coordinate copy/delete with in-place saves across panes on the same root without holding a lock during I/O. Busy/confirmation/response state is bound to the originating session and pane; close/switch flows cancel pre-request UI and wait for accepted mutations. Move, create, rename, upload, cross-session transfer, and overwrite-on-paste remain out of scope.
